# 공개 레포 — 회사 내용·개인정보·민감정보를 넣지 않습니다

이 레포는 GitHub 에 공개됩니다. 코드·테스트·문서·스킬·커밋 메시지·PR 에 아래 내용을 쓰지 않습니다. 한 번 올라간 것은 나중에 이력에서 지워도 이미 복제·색인돼 되돌릴 수 없습니다.

## 넣지 않는 것

- **회사 내용**: 작성자가 일하는 회사와 고객사의 이름·제품·서비스, 사내 레포·서브모듈 경로·브랜치 이름, 사내 git 서버·도메인·URL·IP, 사내 도구 이름, 동료 이름과 계정, 이슈·티켓·PR 번호, 메신저 채널과 문서 링크, 회사 일의 내용.
- **개인정보**: 실제 이메일(커밋 작성자는 GitHub noreply 주소만 씁니다), 전화번호, 주소, 홈 경로(`/Users/<이름>` 등)와 기기 이름, 개인 계정의 내부 ID.
- **민감정보**: 토큰·API 키·비밀번호, 키체인 항목, 실제 장부(`*.db`)·워커 보고·대화 기록·로그를 그대로 붙인 것.

## 대신 쓰는 것

- 실제 사례는 일반화합니다. 예: "서브모듈이 있는 레포의 PR 머지 준비", "원격 git 서버".
- 예시 값은 지어낸 값을 씁니다. 예: `example.com`, `<레포>`, `<홈>`, `#1`.
- 실측 기록에는 수치와 동작만 남기고, 어디서 누구의 무슨 일을 했는지는 뺍니다.

## 커밋·push 전에

- `git diff --cached` 와 커밋 메시지를 읽고 위 내용이 없는지 확인합니다. 회사 일을 하다가 nod 를 고쳤다면 그 일의 이름·번호·사람이 문서와 커밋 메시지에 섞이기 쉽습니다.
- 넣어도 되는지 애매하면 커밋하지 말고 사용자에게 묻습니다.
- 이미 커밋했다면, push 전에는 그 커밋을 고쳐(`git commit --fixup` 뒤 `rebase --autosquash`) 이력에서 없앱니다. 이미 push 했다면 사용자에게 바로 알립니다.
