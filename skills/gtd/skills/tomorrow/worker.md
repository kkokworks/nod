# 내일 준비: 워커가 할 일

정해진 시각에 nod 트리거의 워커로 내일 준비를 합니다. 지시 아래에 붙은 데이터만 씁니다. 사용자에게 묻지 않고, 장부를 바꾸지 않습니다.

- 붙는 데이터: 다음 근무일, 그날의 `nod today`, `nod todo check --json`(`trust`), 열린 할 일(`nod todo --json`), 켠 도구 중 스크립트가 있는 것(plane·forgejo)의 출력.
- 메신저처럼 MCP 로 읽는 도구는 붙지 않습니다. 다음 날 사람이 부르는 훑기에서 봅니다.

1. 업무 도구 출력에서 할 일 후보를 고르고, `trust.stale` 의 대기마다 "다시 묻기" 후보를 만듭니다.
2. 후보마다 [ledger.md](../../ledger.md) 의 "명료화"로 제안을 만들어, 보고의 마지막 줄 위에 한 줄씩 적습니다. 원래 제목은 그대로 두고, 제안은 메모 마지막 줄에 둡니다.
   ```
   NOD: in {"title": "<원래 제목>", "notes": "<출처 한 줄>\n제안: <고친 제목> / <놓을 상태>", "link": "<주소>", "source": "<도구>", "key": "<원본 ID>"}
   ```
   - 키는 그 도구의 원본 ID 입니다(예: plane 은 이슈 키). 이미 장부에 있는 것은 nod 가 넣지 않습니다.
   - 다시 묻기 후보의 출처는 `again`, 키는 `t<대기 번호>-<since>` 입니다(`since` 는 `trust.stale` 의 그 대기의 값). 다시 물은 기록이 남기 전까지는 다음 날 다시 돌아도 한 번만 들어갑니다.
3. 마지막 줄은 `NOD: done | 받아 적을 것 <N>건, <다음 근무일> 일정 <요약>` 입니다.

nod 는 done 을 검증과 리뷰로 받아들인 뒤에 그 줄들을 받은 일함에 넣습니다. 읽을 수 없는 줄은 돌려보내 다시 쓰게 하고, 한 번에 50건이 넘으면 받지 않습니다.
