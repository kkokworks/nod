# 내일 준비

시작할 때 [ledger.md](../../ledger.md) 를 읽습니다. "내일"은 다음 근무일입니다. 금요일이면 월요일입니다.

1. `nod today <다음 근무일>` 로 그날 일정, 예정, 마감을 봅니다. 켠 도구마다 SOURCE.md 의 "다가오는 것" 칸으로 그날 것도 모읍니다.
2. 오래된 대기: `nod todo check` 의 waiting 줄에 나온 사람 대기마다 "다시 묻기" 다음 행동을 제안합니다. 제목은 "<사람>에게 <무엇> 다시 묻기", 메모에 그 대기 항목(`t<번호>`)을 적습니다. 다시 물었으면 대기 항목에 `--add-note '<MM-DD> 다시 물음'` 을 남깁니다. 그래야 그날부터 다시 셉니다.
3. [gtd:scan](../scan/SKILL.md) 의 업무 도구 훑기와 끝난 일 정리도 함께 합니다.
4. 후보를 gtd:scan 의 훑기 4·5단계처럼 표로 보여 주고 고른 것만 놓습니다.
5. 내일 일정과 [gtd:today](../today/SKILL.md) 의 "오늘 집중 고르기" 후보 표를 보여 줍니다. 사용자가 지금 고르면 `--focus <다음 근무일>` 로 표시하고, 아니면 다음 날 고릅니다.

끝: 고른 후보가 놓였고, 다음 근무일의 일정·마감·집중 후보를 보여 줬습니다.

## 사람 없이 돌리기 등록

정해진 시각에 nod 트리거의 워커가 내일 준비를 합니다. 워커는 샌드박스 안이라 장부와 업무 도구에 닿지 못하므로, `<gtd 폴더>/tomorrow.ts` 가 샌드박스 밖에서 데이터를 모아 지시 아래에 붙입니다. 워커가 받아 적을 것을 보고하면 nod 가 대신 받은 일함에 넣고, 다음 날 [gtd:clarify](../clarify/SKILL.md) 에서 사용자가 제안을 승인하거나 고칩니다.

시각을 사용자에게 묻고, 아래 한 줄을 `!` 로 실행해 달라고 부탁합니다. 등록할 때 `--source` 를 한 번 돌리는데, 캘린더와 업무 도구는 Claude 의 샌드박스 안에서 읽히지 않기 때문입니다. `<gtd 폴더>` 는 실제 경로로 바꿔 보여 줍니다.

```sh
! nod trigger add '0 18 * * MON-FRI' '내일 준비를 사람 없이 하세요. 지시는 <gtd 폴더>/skills/tomorrow/worker.md 입니다.' --source 'bun <gtd 폴더>/tomorrow.ts'
```
