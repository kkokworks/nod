# 내일 준비

시작할 때 [ledger.md](../../ledger.md) 를 읽습니다. "내일"은 다음 근무일입니다. 금요일이면 월요일입니다.

1. `nod today <다음 근무일>` 로 그날 일정, 예정, 마감을 봅니다. 켠 도구마다 SOURCE.md 의 "다가오는 것" 칸으로 그날 것도 모읍니다.
2. 오래된 대기: `nod todo check` 의 waiting 줄에 나온 사람 대기마다 "다시 묻기" 다음 행동을 제안합니다. 제목은 "<사람>에게 <무엇> 다시 묻기", 메모에 그 대기 항목(`t<번호>`)을 적습니다. 다시 물었으면 대기 항목에 `--add-note '<MM-DD> 다시 물음' --from waiting` 을 남깁니다. 그래야 그날부터 다시 셉니다. 그사이 대기가 풀렸으면 거절되니, 다시 읽어 그 항목을 어떻게 할지 묻습니다.
3. [gtd:scan](../scan/SKILL.md) 의 업무 도구 훑기와 끝난 일 정리도 함께 합니다.
4. 후보를 gtd:scan 의 훑기 4·5단계처럼 표로 보여 주고 고른 것만 놓습니다.
5. 내일 일정과 [gtd:today](../today/SKILL.md) 의 "오늘 집중 고르기" 후보 표를 보여 줍니다. 사용자가 지금 고르면 `--focus <다음 근무일> --from <후보로 읽은 상태>` 로 표시하고, 아니면 다음 날 고릅니다.

상태를 바꾸는 명령에는 모두 표를 만들 때 읽은 상태를 `--from` 으로 붙이고, 거절되면 다시 읽어 다시 확인받습니다(ledger.md 의 "읽은 상태로 바꾸기").

끝: 고른 후보가 놓였고, 다음 근무일의 일정·마감·집중 후보를 보여 줬습니다.

## 사람 없이 돌리기 등록

정해진 시각에 `<gtd 폴더>/tomorrow.ts` 가 내일 준비 작업을 nod 에 넣고(`nod add`), 그 작업의 워커가 내일 준비를 합니다. 워커는 샌드박스 안이라 장부와 업무 도구에 닿지 못하므로, `tomorrow.ts` 가 샌드박스 밖에서 데이터를 모아 지시 아래에 붙입니다. 워커가 받아 적을 것을 보고하면 nod 가 대신 받은 일함에 넣고, 다음 날 [gtd:clarify](../clarify/SKILL.md) 에서 사용자가 제안을 승인하거나 고칩니다.

`tomorrow.ts` 는 OS 의 cron 이 부릅니다. 캘린더와 업무 도구는 Claude 의 샌드박스 안에서 읽히지 않고 crontab 도 사용자의 것이라, 등록은 사용자가 `!` 로 합니다.

1. `nod schedule` 로 스케줄이 켜져 있는지 봅니다. 꺼져 있으면 `tomorrow.ts` 가 거절하니, 사용자에게 자기 터미널에서 `nod schedule on` 을 한 번 실행해 달라고 합니다. 워커는 그때 켠 셸의 PATH·Claude 설정으로 뜹니다.
2. 시각을 사용자에게 묻습니다(예: 평일 18시).
3. `command -v bun` 으로 bun 의 절대 경로를 찾습니다. cron 은 짧은 PATH 로 돌기 때문입니다. nod 홈이 기본(`~/.nod`)이 아니면 줄의 `"<bun 절대 경로>"` 앞에 `NOD_HOME="<경로>"` 를 붙입니다.
4. 아래 한 줄의 시각과 `<…>` 를 실제 값으로 바꿔 보여 주고, `!` 로 실행해 달라고 부탁합니다. 경로는 공백이 있어도 되게 큰따옴표 안에 둡니다. cron 은 `%` 를 줄바꿈으로 읽으니, 경로에 `%` 가 있으면 `\%` 로 씁니다.

```sh
! (crontab -l 2>/dev/null; echo '0 18 * * 1-5 "<bun 절대 경로>" "<gtd 폴더>/tomorrow.ts" >> "<nod 홈>/tomorrow.log" 2>&1') | crontab -
```

- 돌 때마다 `<nod 홈>/tomorrow.log` 에 `added task n<번호>` 나 오류가 남습니다.
- 지우려면 `crontab -e` 로 그 줄을 지웁니다.
- cron 은 컴퓨터가 잠든 사이 지나간 시각을 나중에 돌리지 않습니다. 같은 날 두 번 돌면 작업이 둘 생깁니다.
