# Wide research

항목마다 `wide-item` 에이전트를 하나씩 띄워 같은 칸을 조사하게 하고, 결과를 표 한 장으로 합친다. 너는 코디네이터다. 범위를 정하고, 에이전트를 띄우고, 결과를 모으는 일만 하고 조사는 에이전트에게 맡긴다. 항목마다 새 에이전트를 쓰는 이유는, 한 맥락에서 항목 수십 개를 조사하면 뒤로 갈수록 조사가 얕아지기 때문이다.

이 스킬의 폴더(이 SKILL.md 가 있는 곳)를 `<skill>`, 이번 조사의 작업 폴더를 `<dir>` 로 부른다.

## 1. 범위 정하기

항목·칸·조건을 표로 정리해 사용자에게 보여 주고 확인받는다.

- **항목**: 사용자가 준 목록. 목록부터 찾아야 하면 그 목록을 먼저 조사해(검색 몇 번, 또는 deep-research) 확인받는다.
- **칸**: 이름 + 뜻 + 형식. 예: "직원 수 — 가장 최근 공식 발표 기준 정규직 수, 숫자와 기준 시점". 형식이 모호하면 에이전트마다 다른 기준으로 채워 표가 맞지 않는다.
- **조건**: 기준 시점·지역·통화처럼 모든 항목에 공통인 것.
- **대상**: 회사·제품·도구·공개된 기관과 공인. 일반 개인에 관한 조사는 개인정보를 모으는 일이라 진행하지 않고 사용자에게 그 이유를 말한다.
- **규모**: 한 번에 항목 50개까지. 결과가 이 세션으로 돌아오기 때문이다. 더 많으면 50개씩 나눠 여러 번 돌리겠다고 알린다.

완료 기준: 사용자가 항목 수·칸·조건에 동의했다.

## 2. 같은 사이트 몰림 점검

항목이 10개 이상이고, 칸을 채우려면 대부분의 항목에서 같은 사이트를 열어야 하는지 본다. 예를 들어 회사 30곳을 모두 같은 데이터베이스 사이트에서 찾는 경우다. WebFetch 는 이 PC 에서 그 사이트로 직접 요청하므로, 몰리면 사이트가 자동으로 차단할 수 있고, 공인 IP 를 함께 쓰는 사람들까지 그 사이트에 못 들어가게 된다. 그 경우 사용자에게 이 위험을 알리고 진행 확인을 받은 뒤, **배치 크기를 1** 로 정해 에이전트를 하나씩 돌린다. 몰리지 않으면 배치 크기는 10 이다.

완료 기준: 배치 크기(10, 또는 확인받은 1)가 정해졌다.

## 3. 작업 폴더

사용자가 정한 곳, 없으면 이 세션의 scratchpad, 그것도 없으면 현재 작업 폴더 아래에 `wide-research/<제목>/` 을 만든다. 제목은 짧게, 이전 조사와 겹치지 않게 짓는다. 그 안에 `plan.json` 을 쓴다.

```json
{
  "title": "<제목>",
  "conditions": "<조건>",
  "columns": [{ "name": "<칸 이름>", "spec": "<뜻과 형식>" }],
  "items": ["<항목>", "..."]
}
```

완료 기준: `<dir>/plan.json` 이 1단계에서 확인받은 내용 그대로 있다.

## 4. 조사

배치 크기만큼의 항목을 한 메시지에서 Agent 로 띄운다. 칸 이름은 plan.json 과 글자까지 같게 쓴다.

```
Agent(
  subagent_type="wide-item",
  description="<항목> 조사",
  prompt="항목: <항목 이름>
조건: <conditions>
칸:
- <칸 이름>: <spec>
- <칸 이름>: <spec>"
)
```

`wide-item` 이 없다는 오류가 나오면 에이전트 정의(이 레포의 `agents/wide-item.md` 를 `~/.claude/agents/` 에 링크한 것)가 방금 생겨 아직 목록에 반영되지 않은 경우다(만든 뒤 몇 분 걸린 적이 있다). 사용자에게 알리고 잠시 뒤 다시 띄우며, 계속 없으면 세션을 다시 시작해 달라고 한다. `wide-item` 은 웹 글 속 지시가 파일·명령에 닿지 못하게 도구를 WebSearch·WebFetch 로 제한한 에이전트라, 도구 제한이 없는 general-purpose 가 대신하지 않는다.

결과가 돌아오는 대로 받은 JSON 한 줄을 고치지 않고 `add` 로 덧붙인다(한 결과 = 한 줄). 배치의 결과가 모두 들어오면 다음 배치를 띄운다.

```sh
bun <skill>/merge.ts add <dir> <<'EOF'
<받은 JSON 한 줄>
EOF
```

`add` 는 JSON 이 아닌 줄이 하나라도 있으면 아무것도 넣지 않는다. 깨진 줄은 어느 항목의 것인지 알 수 없어서, 파일에 들어가면 다시 조사한 줄로도 대신할 수 없기 때문이다. 거절된 항목은 다음 배치에 한 번 더 맡긴다. 두 번째도 실패하면 모든 칸을 null 로, note 를 `"조사 실패: <이유>"` 로 적은 줄을 직접 덧붙인다.

완료 기준: plan.json 의 모든 항목에 results.jsonl 의 줄이 있다.

## 5. 합치기

```sh
bun <skill>/merge.ts <dir>
```

`table.md`·`table.csv` 를 만들고 요약을 출력한다. 형식이 틀린 줄이나 결과가 없는 항목이 있으면 아무것도 만들지 않고 그 이유를 줄 번호와 함께 출력한다. 그 항목만 4단계 방식으로 다시 맡겨 새 줄을 덧붙이고(같은 항목은 마지막 줄이 이긴다) 다시 합친다.

완료 기준: merge.ts 가 오류 없이 끝났다.

## 6. 보고

merge.ts 요약의 숫자(항목 수, 채운 칸/전체 칸, 빈칸 목록)와 `table.md`·`table.csv` 의 절대 경로를 알린다. 항목이 15개 이하면 table.md 의 표를 답에 그대로 보여 준다. 마지막에 "숫자와 사실은 각 칸의 출처 링크로 확인이 필요합니다" 라고 붙인다. 에이전트는 출처를 달아도 틀릴 수 있고, 이 표를 쓰는 사람이 그 확인을 해야 한다.
