# 트리거와 알림

## 트리거

"매일 아침 …", "새 이슈가 오면 …" 처럼 정해진 때나 새 항목마다 할 일은 트리거로 맡깁니다: `nod trigger add '<cron>' '<지시>' [--source '<명령>'] [--repo … --branch <접두어>] [--check …]`.

- 레포에서 하는 트리거는 `--branch` 에 브랜치 접두어를 줍니다(예: `chore/weekly-deps`). 이름을 지어 줄 사람이 없으니 작업마다 `<접두어>/<작업 번호>` 브랜치가 됩니다.

- cron 은 5칸이고 로컬 시간입니다(예: 평일 9시는 `0 9 * * MON-FRI`).
- `--source` 명령은 한 줄에 항목 하나를 출력합니다. 탭이 있으면 탭 앞이 항목의 키이고, 그 키가 작업의 이슈가 됩니다. 등록할 때 이미 있는 항목은 작업이 되지 않고, 그 뒤 새로 나온 항목마다 작업이 하나씩 생깁니다.
- source 명령은 사용자의 셸 권한으로 샌드박스 없이 돕니다. 조회만 하는 명령으로 짜고, 등록 전에 사용자에게 일정·지시·명령을 보여 주고 확인을 받습니다. 트리거는 사람이 없을 때도 워커를 띄우기 때문입니다.
- 트리거는 `nod schedule on` 으로 켠 매분 tick 이 돌립니다(macOS launchd). 등록할 때 스케줄이 꺼져 있다고 나오면, 사용자에게 자기 터미널에서 `nod schedule on` 을 한 번 실행해 달라고 합니다. 켠 셸의 `PATH`·Claude 설정으로 워커가 돌기 때문에, 세션이 대신 켜지 않습니다. 켜진 상태와 그 환경은 `nod schedule` 로 봅니다.
- 목록은 `nod trigger ls`(다음 실행 시각, 마지막 실패), 삭제는 `nod trigger rm <번호>`.

## 알림

사람이 자리에 없을 때도 결정을 알고 싶어 하면 `~/.nod/notify` 실행 파일을 만들어 줍니다. 결정이 열리거나 작업이 끝나면 nod 가 JSON 을 stdin 으로 넘겨 부릅니다. 무엇으로 알릴지(macOS 알림, 개인 Slack 웹훅 등)는 사용자가 고릅니다.
