# 내일 준비

사용자가 "내일 준비해 줘"로 부르거나, 정해진 시각에 사람 없이 돕니다(아래 "사람 없이 돌리기"). "내일"은 다음 근무일입니다. 금요일이면 월요일입니다.

1. `nod today <다음 근무일>` 로 그날 일정, 예정, 마감을 봅니다. 켠 도구마다 SOURCE.md 의 "다가오는 것" 칸으로 그날 것도 모읍니다.
2. 오래된 대기: `nod todo check` 의 waiting 줄에 나온 사람 대기마다 "다시 묻기" 다음 행동을 제안합니다. 제목은 "<사람>에게 <무엇> 다시 묻기", 메모에 그 대기 항목(`t<번호>`)을 적습니다. 다시 물었으면 대기 항목에 `--add-note '<MM-DD> 다시 물음'` 을 남깁니다. 그래야 그날부터 다시 셉니다.
3. [scan.md](scan.md) 의 업무 도구 훑기와 끝난 일 정리도 함께 합니다.
4. 후보를 scan.md 의 훑기 4·5단계처럼 표로 보여 주고 고른 것만 놓습니다.
5. 내일 일정과 [focus.md](focus.md) 의 후보 표를 보여 줍니다. 사용자가 지금 고르면 `--focus <다음 근무일>` 로 표시하고, 아니면 다음 날 고릅니다.

끝: 고른 후보가 놓였고, 다음 근무일의 일정·마감·집중 후보를 보여 줬습니다.

## 사람 없이 돌리기

정해진 시각에 nod 트리거의 워커가 돕니다. 워커는 샌드박스 안이라 장부를 열거나 업무 도구에 닿지 못합니다. 그래서 트리거의 `--source` 인 `tomorrow.ts` 가 샌드박스 밖에서 데이터를 모아 지시 아래에 붙여 주고, 워커가 받아 적을 것을 보고하면 nod 가 대신 받은 일함에 넣습니다.

- 붙는 데이터: 다음 근무일, 그날의 `nod today`, `nod todo check --json`, 열린 할 일(`nod todo --json`), 켠 도구 중 스크립트가 있는 것(plane·forgejo)의 출력.
- 빠지는 것: MCP 로 읽는 도구(Slack 등)는 워커가 쓰려면 사람의 허락이 필요해 넣지 않습니다. 다음 날 사람이 부르는 훑기에서 봅니다. 완료·집중처럼 장부를 바꾸는 일도 하지 않습니다.

### 등록

사용자에게 아래 한 줄을 `!` 로 실행해 달라고 부탁합니다. 등록할 때 `--source` 를 한 번 돌리는데, 캘린더와 업무 도구는 Claude 의 샌드박스 안에서 읽히지 않기 때문입니다. 시각은 사용자에게 묻습니다.

```sh
! nod trigger add '0 18 * * MON-FRI' 'nod 스킬의 내일 준비를 사람 없이 하세요. 지시는 <스킬 폴더>/tomorrow.md 의 "워커가 할 일"입니다.' --source 'bun <스킬 폴더>/tomorrow.ts'
```

### 워커가 할 일

1. 지시 아래에 붙은 데이터만 씁니다. 사용자에게 묻지 않습니다.
2. 업무 도구 출력에서 할 일 후보를 고르고, `trust.stale` 의 대기마다 "다시 묻기" 후보를 만듭니다.
3. 후보마다 [todos.md](todos.md) 의 "명료화"로 제안을 만들어, 보고의 마지막 줄 위에 한 줄씩 적습니다. 원래 제목은 그대로 두고, 제안은 메모 마지막 줄에 둡니다.
   ```
   NOD: in {"title": "<원래 제목>", "notes": "<출처 한 줄>\n제안: <고친 제목> / <놓을 상태>", "link": "<주소>", "source": "<도구>", "key": "<원본 ID>"}
   ```
   - 키는 그 도구의 원본 ID 입니다(예: plane 은 이슈 키). 이미 장부에 있는 것은 nod 가 넣지 않습니다.
   - 다시 묻기 후보의 출처는 `again`, 키는 `t<대기 번호>-<since>` 입니다(`since` 는 `trust.stale` 의 그 대기의 값). 다시 물은 기록이 남기 전까지는 다음 날 다시 돌아도 한 번만 들어갑니다.
4. 마지막 줄은 `NOD: done | 받아 적을 것 <N>건, <다음 근무일> 일정 <요약>` 입니다.

nod 는 워커의 done 을 검증과 리뷰로 받아들인 뒤에 그 줄들을 받은 일함에 넣습니다. 누가는 `worker:<작업>` 으로 남습니다. 읽을 수 없는 줄은 워커에게 돌려보내 다시 쓰게 하고, 한 번에 50건이 넘으면 받지 않습니다. 다음 날 받은 일함을 비울 때([clarify.md](clarify.md)) 사용자는 메모의 제안을 승인하거나 고치기만 하면 됩니다.
