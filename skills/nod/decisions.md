# 결정 전하기

결정 알림이 오면 결정 번호, 작업, 질문을 그대로 사용자에게 전합니다. 답은 사용자의 말로만 넘깁니다.

- `question`·`failed`·`check_failed`: 사용자가 답하면 `nod <결정> '<답>'`. 사용자의 말을 그대로 넘깁니다. 답은 살아 있는 같은 세션에 들어갑니다. `check_failed` 는 검증 명령이나 독립 리뷰가 재시도를 다 쓰고도 실패한 것입니다. 질문에 리뷰어의 지적이 들어 있으면 그것도 함께 보여 줍니다. 질문이 `It has waited on background work` 로 시작하면 워커가 띄워 둔 서브 에이전트·셸이 한 시간이 넘도록 끝나지 않은 것이니 그 점을 전합니다. 질문에 `nod passes on at most 4 between two tasks` 가 있으면 두 작업의 워커가 서로 말을 네 번 넘게 주고받으려 해 nod 가 그 보고의 메시지를 모두 멈춘 것입니다. 그 메시지들을 보여 주고, 사용자가 넘기라고 하면 `nod tell <받을 작업> '<메시지>'` 로 넘긴 뒤 결정에 답합니다.
- `permission`: 워커가 권한 확인 화면에서 기다리는 중입니다. 결정 내용에 화면이 들어 있으니 무엇을 하려는지 보여 줍니다. 사용자가 허락하면 `nod <결정> yes`, 아니면 사용자의 말을 그대로 `nod <결정> '<말>'` 로 넘깁니다(거절과 함께 그 말이 워커에게 갑니다).
- `trust`: 워커가 Claude Code 가 아직 신뢰하지 않는 레포에서 신뢰 확인을 기다립니다. 신뢰하면 그 레포에 들어 있는 Claude 설정·훅이 워커에서 실행된다는 점을 함께 전합니다. 사용자가 허락하면 `nod <결정> yes`, 아니면 사용자의 말을 그대로 넘깁니다(작업이 취소됩니다).
- `rule`: 검증에 되돌려졌거나 실패한 작업을 회고 워커가 돌아보고, 앞으로 모든 워커가 받을 규칙 한 줄을 제안했습니다. 규칙과 회고 번호(`r<n>`), 그 계기가 된 작업을 보여 줍니다. 사용자가 받아들이면 `nod <결정> yes` 로 장부의 규칙에 들어가 그 회고와 이어지고, 아니면 사용자의 말을 넘겨 버립니다. 문구를 고치고 싶어 하면 받아들인 뒤 `nod rule ls` 로 번호를 찾아 `nod rule edit <번호> '<문구>'` 로 고칩니다. 나중에 빼고 싶어 하면 `nod rule off <번호>` 입니다(지우기는 없음). 규칙을 바꾸는 명령도 사용자가 말한 대로만 부릅니다.
- `interrupted`: 워커의 Claude Code 가 답하던 도중에 끝났습니다(계정 전환·충돌로 칸 안에서 다시 떴거나, 재부팅·tmux 종료로 칸이 사라짐). 또는 띄우자마자 거듭 끝나서 nod 가 다시 띄우기를 멈췄습니다(로그인이 없는 등, 질문에 마지막 화면이 들어 있음). 그 차례의 일이 일부 됐을 수 있다는 점과 질문에 든 화면을 전합니다. 사용자가 이어 가라고 하면 사용자의 말을 그대로 `nod <결정> '<말>'` 로 넘깁니다. 워커는 같은 대화에서 "차례가 끊겼으니 된 것부터 확인하라"는 말과 함께 받습니다. 화면에 로그인 문제가 보이면 먼저 고친 뒤 답하라고 안내합니다.
- 사용자가 그 작업을 그만두라고 하면 `nod drop <결정>`. 세션도 닫힙니다. 이미 끝난 작업(succeeded·cancelled)에 남은 결정은 답하든 drop 하든 결정만 닫히고 작업은 그대로입니다.
- `nod watch` 로 받는 세션이면, 답한 뒤 watch 가 끝나 있으면 다시 겁니다. 프로젝트 세션은 nod 가 알림을 보내므로 걸지 않습니다.
