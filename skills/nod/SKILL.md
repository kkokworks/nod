# nod

`nod` CLI 가 엔진이고 이 세션은 앞단입니다. 작업마다 nod 가 tmux 안에 실제 Claude Code 세션(워커)을 띄웁니다. 워커는 한 작업 동안 같은 세션에서 맥락을 유지하고, 질문·검증 실패·권한 확인은 결정으로 장부(`~/.nod`)에 올라옵니다. 이 세션은 일을 나눠 맡기고, 결정을 사용자에게 전하고, 답을 워커에게 돌려주고, 워커가 끝낸 결과를 밖으로 내보냅니다.

nod 는 작업을 `n<번호>`, 결정을 `d<번호>` 로 씁니다. 할 일 `t<번호>`, 회고 `r<번호>`, 프로젝트 `p<번호>` 와 같습니다. 명령은 작업·결정의 맨 숫자도 받지만, 사용자에게 전하거나 명령을 쓸 때는 글자를 붙입니다. `#` 은 `owner/repo#80` 같은 이슈·PR 표기에만 씁니다.

`nod` 명령이 없으면 nod 레포에서 `bun link` 를 하라고 안내합니다. tmux 도 필요합니다.

## 할 일에 맞는 파일

지금 할 일에 맞는 파일을 읽고 그 절차를 따릅니다.

| 할 일 | 파일 |
|---|---|
| 인자 없는 `/nod`, 진행 상황이나 남은 일 보기 | [results.md](results.md) 의 "상태 보기" |
| 일 맡기기, 이미 있는 작업에 후속 지시 | [delegate.md](delegate.md) |
| 결정 알림 전하기, 사용자의 답 넘기기 | [decisions.md](decisions.md) |
| 자리를 비울 때 알림(`~/.nod/notify`) | [decisions.md](decisions.md) 의 "자리를 비울 때 알림" |
| 결과 내보내기(push·PR·게시)와 링크, 리뷰 반영, 정리(gc) | [results.md](results.md) |
| 프로젝트(업무 묶음) 하나를 맡아 nod 로 굴리기 | [project.md](project.md) |
| 다른 루트 세션(일반·프로젝트)에 말 보내기, 받은 말에 답하기 | [project.md](project.md) 의 "다른 루트 세션에 말 보내기" |
| 이 세션이 오케스트레이터·릴레이일 때, 세션에 역할 주기 | [delegate.md](delegate.md) 의 "오케스트레이터·릴레이 세션" |

루트 세션은 프로젝트마다 사용자가 `nod open <프로젝트>` 로 열고, 한 세션은 한 프로젝트의 일만 맡깁니다. 다른 프로젝트의 일은 할 일로 넣습니다([delegate.md](delegate.md)). 프로젝트에 속하지 않는 세션은 이름으로 열고 역할(`orchestrator`·`relay`)을 갖습니다. 프로젝트의 일은 직접 맡기지 못합니다.

할 일을 받아 적고 정리하는 일(GTD)은 gtd 스킬(`gtd:*`)이 합니다. nod 는 거기 쌓인 할 일을 `nod add --todo t<번호>` 로 맡아 워커에게 시킵니다.

## 늘 지키는 것

- 결정은 사용자의 말로만 답합니다. 답이 뻔해 보여도 사용자가 말하기 전에는 `nod <결정> …` 이나 `nod drop` 을 실행하지 않습니다. 작업을 그만두는 `nod cancel` 도 사용자가 그만두라고 할 때만 실행합니다.
- 바깥에 쓰는 일(push·PR·이슈 댓글·메시지)은 무엇을 올릴지 보여 주고 사용자 확인을 받은 다음 합니다. 사람이 `nod repo` 로 착지를 허락한 레포의 push·PR·머지는 nod 가 그 허락대로 합니다.
- 장부는 `nod` 명령으로만 바꿉니다.

## 그 밖

- 트리거(`nod trigger`)는 없습니다. 사용자가 정해진 때 할 일을 맡기려 하면, 자기 OS 스케줄러(cron·launchd)에 `nod add` 줄을 등록하라고 안내합니다. 스케줄러는 거의 빈 환경으로 띄우므로, 그 줄에 `nod`·tmux·claude 가 있는 `PATH` 와 셸에서 쓰는 `NOD_HOME`·`CLAUDE_CONFIG_DIR`·`TMUX_TMPDIR` 를 줍니다(README 「쓰기」의 트리거 문단). 목록의 항목마다 한 번씩 받으려면 `nod in --source <이름> --key <키>` 로 받아 적습니다(같은 키는 한 번만 들어감).
- 사용자가 워커를 직접 보거나 끼어들고 싶어 하면, 자기 터미널에서 `nod attach <작업>` 을 실행하라고 안내합니다(빠져나올 때는 tmux 의 `Ctrl-b d`). 웹 화면이나 데스크톱 앱의 작업 화면에서 워커 화면을 눌러 바로 칠 수도 있습니다. 이 세션에서는 터미널을 열 수 없습니다. 끝난 지 한 시간이 지난 작업은 칸이 닫혀 있을 수 있고(스케줄의 tick 이 닫음), 그러면 `nod tell` 이 같은 대화로 칸을 다시 엽니다.
- 명령 전체(`peek`·`show`·`stats` 등)는 `nod help` 에 있습니다.
- 워커는 이 셸의 Claude 로그인과 사용자 설정(CLAUDE.md·훅·MCP)을 씁니다. 다른 계정으로 돌리려면 `CLAUDE_CONFIG_DIR=<설정 폴더> nod add …` 로 실행합니다. 계정을 바꾸는 도구를 쓰면 `nod account file <파일>`(또는 `command <명령>`)로 지금 계정을 읽을 곳을 한 번 정해 두면, 바꾼 뒤 워커가 차례 사이에 그 계정으로 다시 뜹니다. 바깥 도구가 바꾼 직후에 알리려면 `nod restart` 를 부릅니다.
- 워커의 Claude Code 가 끝나도(계정 전환, `/exit`, 충돌) nod 는 같은 tmux 칸에서 같은 대화로 다시 띄웁니다. 그래서 칸 안에서 Claude 를 꺼도 워커는 끝나지 않습니다. 작업을 끝내려면 `nod cancel <작업> --reason '<사용자가 말한 이유>'` 를 실행하고(열린 결정이 있으면 `nod drop <결정>` 도 같음, [decisions.md](decisions.md)), 끝난 작업은 `nod gc` 로 정리합니다. 할 일을 drop 하거나 워커에게 `nod tell` 로 그만두라고 전하는 것으로는 작업이 끝나지 않습니다. 워커는 done 으로 끝내고, nod 가 그 보고를 검사·리뷰해 성공으로 남깁니다.
