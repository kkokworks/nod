# nod

`nod` CLI 가 엔진이고 이 세션은 앞단입니다. 요청을 작업으로 바꿔 장부(`~/.nod`)에 넣고, 실행기를 뒤에서 돌리고, 워커가 올린 결정을 사용자에게 전합니다. 결정은 사용자만 내립니다.

`nod` 명령이 없으면 nod 레포에서 `bun link` 를 하라고 안내합니다.

## 인자 없이 `/nod`

`nod`(열린 결정)와 `nod ls`(작업 상태)를 보여 줍니다. 대기(queued) 작업이 있는데 실행기가 없으면 아래 "실행기 띄우기"를 합니다.

## 일 맡기기

1. 요청을 서로 독립인 작업으로 나눕니다. 같은 파일을 고치는 일은 한 작업으로 묶습니다. nod 는 아직 작업 사이 순서를 모릅니다. 요청이 모호하면 나누기 전에 묻습니다.
2. 작업마다 `nod add '<지시>' [--repo <레포 경로>] [--check '<검증 명령>']` 를 실행합니다. 출력이 작업 번호입니다.
   - 워커는 이 지시와 짧은 규칙만 받고 이 대화는 모릅니다. 무엇을, 어디서, 무엇이 되면 끝인지까지 지시에 씁니다.
   - git 레포를 고치는 일은 `--repo` 를 줍니다. 워커는 `nod/<작업>` 브랜치의 worktree 에서 일하고 커밋합니다. 레포가 아니면 빈 작업 폴더(`~/.nod/work/<작업>`)에서 일합니다.
   - 테스트처럼 통과 여부를 명령으로 확인할 수 있으면 `--check` 를 줍니다. nod 가 직접 돌려 보고, 실패하면 같은 세션에 다시 시킵니다. 이 명령은 샌드박스 밖에서 돌므로 테스트·빌드 명령만 씁니다.
   - 워커는 샌드박스 안에서 작업 폴더에만 쓸 수 있고, 네트워크는 npm 레지스트리만 열려 있습니다. 웹 조사나 외부 접속이 필요한 일은 맡기지 말고 사용자에게 그렇다고 알립니다.
3. 맡긴 작업(번호와 한 줄 요약)을 사용자에게 알리고 실행기를 띄웁니다.

## 실행기 띄우기

1. Bash `run_in_background` 로 `nod run` 을 실행합니다. 끝날 때까지 세션을 막으므로 앞에서 돌리지 않습니다.
   - `already running` 으로 끝나면 그대로 둡니다. 돌고 있는 실행기가 1초 안에 새 작업과 답을 가져갑니다.
2. Monitor 로 `nod watch` 를 겁니다(timeout 은 최대로). 결정이 열릴 때마다 알림이 한 건씩 옵니다. 실행기가 끝나면 함께 끝나고, 시간이 다 돼 끝났는데 실행기가 아직 돌면 다시 겁니다.
3. 결정 알림이 오면 결정 번호, 작업, 질문을 그대로 사용자에게 전합니다.
4. `nod run` 이 끝났다는 알림이 오면 출력을 보고 정리해 알립니다: 성공한 작업의 요약, 레포 작업이면 확인할 브랜치(`nod/<작업>`), 오류, 남은 결정(`nod`).

## 결정 전하기

- 사용자가 답하면 `nod <결정> '<답>'` 을 실행합니다. 사용자의 말을 그대로 넘깁니다. 워커는 자기가 한 질문을 기억하므로 짧은 답도 됩니다.
- 사용자가 그 작업을 그만두라고 하면 `nod drop <결정>` 을 실행합니다.
- 답한 뒤 실행기가 돌고 있지 않으면 띄웁니다.
- 🔴 결정을 대신 내리지 않습니다. 답이 뻔해 보여도 사용자의 말 없이 `nod <결정> …` 이나 `nod drop` 을 실행하지 않습니다.

## 그 밖

- 한 작업의 이력은 `nod show <작업>`, 효과 측정은 `nod stats` 입니다.
- `nod gc` 는 파일을 지우므로 사용자가 요청할 때만 실행합니다.
- 장부 DB 를 직접 고치지 않습니다. 모든 변경은 `nod` 명령으로 합니다.
- 워커는 이 셸의 Claude 로그인을 씁니다. 다른 계정으로 돌리려면 `CLAUDE_CONFIG_DIR=<설정 폴더> nod run` 으로 실행합니다.
